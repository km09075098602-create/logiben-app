# ロジ弁 お弁当注文・管理アプリ(試作版)

松江市の会社向けお弁当食事補助サービス「ロジ弁」(運営:達磨商事、2027年1月開始予定)の注文・管理アプリです。

## いまできること(試作 v0.9)

| 画面 | できること |
|---|---|
| ログイン(`/`) | 社員:会社コード+社員番号 / 会社の担当者:会社コード+ログインID / お店:ログインID / 管理者:ログインID(どれもパスワードつき) |
| 会社の担当者の画面(`/company.html`) | 自社の月ごとの請求額・食数・利用人数、ご利用明細(印刷可)、社員ごとの内訳(CSV保存可)、日ごとの注文一覧。**自社の分しか見られません** |
| お店の画面(`/shop.html`) | **注文**:日ごとの注文数(締め切り前は「受付中」、後は「確定」)、お弁当ごとの数、お届け先(会社・部署)ごとの中身(印刷可)<br>**メニュー**:自分のお店のメニューの追加・値段や説明の変更・販売停止<br>**お支払い**:2週間ごとのお支払い明細。**自分のお店の分しか見られません** |
| 社員の注文画面(`/order.html`、スマホ向け) | 日付を選んでお弁当を注文・変更・取り消し(締め切りまで)。お弁当ごとに「あなたの支払い額」を表示。今月の会社負担の使用状況をメーターで表示し、上限の80%を超えたら注意、上限に達したら全額自己負担になることをお知らせ |
| 管理者画面(`/admin.html`) | 日付ごとの注文数、お店ごと・お弁当ごとの数と金額、会社・部署順の注文一覧(印刷可)。締め切り時刻などの**設定の変更** |
| 登録画面(`/manage.html`、管理者) | **お店とメニュー**:お店の追加・名前変更・停止、メニューの追加・値段や説明の変更・販売停止、お店のログイン用アカウント<br>**会社と社員**:担当者のアカウント、会社の追加・変更・停止、社員の追加(1人ずつ / CSVでまとめて)・変更・停止、パスワードの再発行。初期パスワードは自動で作られ、CSVで保存して社員に配れます |
| 印刷画面(`/print.html`、管理者) | **名前シール**:A4ラベル用紙に「会社名・名前・部署・お弁当・日付とお店」を印刷。用紙の種類、何枚目から印刷するか、位置の微調整、試し刷り用の枠線。<br>**配達表**:会社ごとに1ページ。お弁当ごとの数、部署ごとの名前一覧(受け取りチェック欄つき)。<br>どちらも日付・お店・会社で絞り込みできます |
| 請求画面(`/billing.html`、管理者) | **会社への請求(月ごと)**:会社ごとの食数・会社負担分・利用料・消費税・請求額、社員ごとの内訳。会社ごとの明細を印刷できる<br>**お店への支払い(2週間ごと)**:お店ごとのお弁当代・営業代行料・支払額、お弁当ごとの数。お店ごとの明細を印刷できる<br>**CSV保存**:注文の明細 / 会社ごとの請求 / 社員ごとの内訳(月ごと)、お店への支払い(期間ごと) |

#### 名前シールの印刷のコツ
- 印刷するときは、ブラウザの印刷画面で「倍率:100%(実際のサイズ)」「余白:なし」にする
- 初めて使う用紙では、「ラベルの枠を印刷する」をオンにして普通の紙に試し刷りし、ラベル用紙に重ねて位置を確認する。ずれていたら「位置の微調整」で直す(設定はそのパソコンに記憶される)
- 用紙の寸法は `public/labels.js` にまとめてある。使う用紙が決まったら、パッケージの寸法に合わせて直すか追加する

#### 請求・支払いの計算(仮決め・`src/billing.js`)
- **会社への請求** = 会社負担分(お弁当代の半額の合計・税込・上限あり)+ サービス利用料(150円 × 食数・税抜)+ 利用料の消費税10%
  - 利用料は、会社負担の上限に達したあとの食事にもかかる
  - 社員負担分の合計も「参考」として出す(給料から差し引く場合などに使う)
  - 明細には税率ごとの合計と消費税額も出す(8%対象 / 10%対象)
- **お店への支払い** = お弁当代(税込)の合計 − 営業代行料(合計の10%・税込・1円未満切り捨て)
  - 「2週間」の区切りは、設定の「起点日」(初期値 2027-01-04 月曜)から14日ずつ
- 月や期間が終わる前に開くと「途中経過」と表示される

#### 登録画面の約束ごと
- 削除はせず「停止」にします(過去の注文・請求の記録を残すため)。再開もできます
- メニューの値段を変えても、すでに入っている注文の値段は変わりません(注文時の値段を記録)
- 社員を停止すると、ログインできなくなり、明日以降の注文は取り消されます
- 会社を停止すると、その会社の社員は全員ログインできなくなります
- 社員の一括登録(CSV)は「社員番号, 名前, 部署」の3列。Excel で保存した CSV(Shift_JIS)もそのまま読めます。1人でも間違いがあれば、全員分を登録せずに間違いの行を知らせます

## お金のルール(仮決め)

ルールはすべて `src/rules.js` にまとめてあり、`tests/rules.test.js` の自動テストで確かめています。

- お店はメニューを**税込み価格**で登録する
- 1食ごとに会社が半額を負担する。1円未満の端数は社員の負担
- 会社負担の上限は1人あたり月7,500円(税抜き)。税込みに直すと8,100円(軽減税率8%)
- 上限をまたぐ注文は、会社が残り分だけを負担し、残りは社員の負担。その後のお弁当は社員が全額を負担する
- 上限はお届け日の早い順に使っていく。前の日の注文を取り消すと、あとの日の負担額は自動で計算し直す
- 上限の80%を超えたら社員の画面にお知らせを出す
- 締め切りは、初期設定では当日9:30。管理画面で前日締めに変えたり、時刻を変えたりできる

## お休みの日(`src/holidays.js`・`src/closed-days.js`)

- **土日・祝日は自動でお休み**(注文を受け付けない)。祝日は法律のルールどおりに計算(振替休日・国民の休日も含む。外部サービス不要)
  - 春分の日・秋分の日は計算式で出しているので、毎年2月の官報の発表と念のため照らし合わせる
- **全体の休業日**(年末年始など):管理画面(注文数のページの下)で登録
- **お店ごとの休業日**:お店の画面の「休業日」タブ、または登録画面のお店の欄で登録。その日はそのお店のお弁当だけが選べなくなる
- すでに注文が入っている日を休業日にするときは、確認のうえ、その注文を取り消す(**社員へのお知らせは、いまは手作業**)

上限・税率・利用料・代行料などの数値は、管理画面の「設定」から変えられます。

## だるまランチ(お店で食べる)(`src/orders.js`)

社員が加盟店で食事をしたときの記録。お弁当と**同じ半額・同じ上限**で計算する(仮決め)。

- **使い方**:社員の注文画面の「🍜 だるまランチを使う」→ お店とメニューを選ぶ →(お店の方の前で)「これを食べる」→ 出てきた画面をお店の方に見せる
  - 画面には、会社名・名前・メニュー・利用時刻と、**動いている時計**を表示(画面の写真の使い回しを防ぐ)
- **ルール**:1日1回まで / お弁当を注文した日は使えない(逆も同じ)/ 土日祝・休業日・お店の休業日は使えない
- **取り消し**:社員は自分では取り消せない(食べたあとに消されるのを防ぐため)。会計の間違いなどは、お店が当日中に、または達磨商事がいつでも取り消せる
- **メニュー**:お店のメニューに「種類」を追加(お弁当 / だるまランチ)。お店の画面・登録画面で選ぶ
- **消費税**:だるまランチは店内飲食なので10%(お弁当は8%)。このため**会社負担の上限(月7,500円)は税抜きで数える**ように変更した
  - お弁当だけなら、これまでと同じ結果(税込8,100円分)になる
  - 社員の画面の「使用・残り」も税抜きで表示
- **請求・支払い**:会社への請求は「お弁当(8%)」「だるまランチ(10%)」を分けて表示し、サービス利用料150円は両方の1食ごとにかかる。お店への支払いにも、だるまランチ分を含める(代行料10%を差し引き)

## ポイント還元(`src/points.js`)

- **もらえる**:お弁当・だるまランチとも、食事をした日に1回 **10ポイント**(取り消した注文はもらえない)
- **使える**:Webで注文するとき・だるまランチを使うときに「ポイントを使う」を選ぶ(1回 **50ポイント**まで。1ポイント=1円)
- **計算(B方式)**:使ったポイント分を**先にお食事代から引き、残りを会社と社員で半分ずつ**
  - 例:620円のお弁当に10ポイント → 610円を 会社305円・社員305円
  - お店への支払いは変わらない(ポイント分は達磨商事がお店に払う)。請求明細・CSVに「ポイント(達磨商事負担)」を表示
- **有効期限**:もらった日から **1年**。古いポイントから先に使う
- 数値(もらえる数・期限・1回の上限・使う/使わない)は管理画面の「設定」で変えられる
- 残高は注文の記録から毎回計算する(注文の変更・取り消しでも自動で正しくなる)
- ※ 食事補助の非課税の条件(社員が半分以上を負担)との関係は、税理士に確認すること

## LINEからの注文(`src/line.js`)

社員は、LINE公式アカウントのトークで **注文する / 注文の確認 / 取り消す / 今月の利用状況** ができる(Webと同じルール:締め切り・お休み・半額・上限)。

- **連携のしかた**:Webの注文画面の「LINEでも注文できます」で6けたの連携コード(10分有効)を出し、LINEのトークに送る
- 注文は、ボタンで「日付 → お店ごとのメニュー(自分の支払い額つき)→ これにする」と選ぶ
- 会社負担が上限の8割を超えたときや上限に達したときは、注文の返事の中でお知らせする
- 休業日で注文を取り消したときは、LINE連携している社員にお知らせが届く
- 友だちを解除(ブロック)すると、連携も自動で外れる

**費用**:社員の操作への「返信」は無料・無制限。こちらから送る「お知らせ(プッシュ)」だけが月の無料通数にかぞえられる(無料プランは月200通。超える場合は有料プラン。料金は LINE for Business の公式サイトで最新のものを確認)。ロジ弁がお知らせを送るのは休業日で注文を取り消したときだけなので、通常は無料の範囲に収まる見込み。

### LINEとつなぐ手順(本番)
1. [LINE Official Account Manager](https://manager.line.biz/) で「ロジ弁」の公式アカウントを作る
2. 設定 → Messaging API で「Messaging APIを利用する」をオンにする(LINE Developers のプロバイダーは「達磨商事」など)
3. 応答設定で「応答メッセージ」をオフ、「Webhook」をオンにする
4. [LINE Developers](https://developers.line.biz/) で、そのチャネルの「チャネルシークレット」と「チャネルアクセストークン(長期)」を控える
5. Cloudflare に登録する:
   ```bash
   npx wrangler secret put LINE_CHANNEL_SECRET
   npx wrangler secret put LINE_CHANNEL_ACCESS_TOKEN
   ```
   友だち追加のURL(`https://lin.ee/…`)は `wrangler.toml` の `[vars]` の `LINE_FRIEND_URL` に書く
6. LINE Developers の「Webhook URL」に `https://(公開したアドレス)/api/line/webhook` を入れて「検証」を押す

この設定をしていないあいだは、社員の画面にLINEの案内は出ない(LINEなしでも全機能が使える)。
自分のパソコンで試すときは `.dev.vars.example` を `.dev.vars` にコピーして値を入れる。

## 自分のパソコンで動かす

Node.js(バージョン20以上)が必要です。

```bash
npm install        # 部品のインストール(最初の1回)
npm run db:reset   # データベースを作り、仮データを入れる(何度でもやり直せる)
npm run dev        # http://localhost:8787 で起動
npm test           # お金・締め切りのルールの自動テスト
```

## インターネットに公開する(Cloudflare・無料)

1. https://dash.cloudflare.com/sign-up で Cloudflare のアカウントを作る(無料)
2. `npx wrangler login` を実行し、ブラウザでログインする
   (または、Cloudflare の画面で「APIトークン」を作り、`CLOUDFLARE_API_TOKEN` という環境変数に入れる)
3. `npx wrangler d1 create logiben` を実行し、表示された `database_id` を `wrangler.toml` に貼る
4. `npx wrangler d1 execute logiben --remote --file=db/schema.sql` でデータベースの形を作る
5. 中身を入れる(どちらか)
   - **お試し版**(仮の会社・社員・お店つき):`npx wrangler d1 execute logiben --remote --file=db/seed.sql`
   - **本番**(設定と管理者だけ):`node scripts/make-production-init.mjs` を実行して表示される**管理者パスワードを控え**、
     `npx wrangler d1 execute logiben --remote --file=db/production-init.sql`
6. `wrangler.toml` の `DEMO_MODE` を、お試し版なら `"1"`、本番なら `"0"` にする(ログイン画面のお試し用アカウントの案内が出るかどうか)
7. `npm run deploy` を実行すると、`https://logiben.(あなたのID).workers.dev` で公開される

※ お試し版のパスワード(demo1234 / admin1234)は誰でも知っているものです。お試し版のURLは関係者だけに伝え、本番は必ず「本番」の手順で作り直してください。

### 本番で使い始めたあとの注意
`db/schema.sql` を本番のデータベースに実行すると、**すべてのデータが消えます**(最初の1回だけ使う)。
使い始めたあとにデータの形を変えるときは、データを消さない変更手順(マイグレーション)を別に用意します。
